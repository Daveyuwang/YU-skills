# Research Ideas: Source Notes

Source: YU's guidance in the project conversation. The
[research-ideas skill](../skills/research-ideas/SKILL.md) separates novelty
assessment from implementation and experiment planning for a chosen direction.
It preserves the user's constructive default and the explicit stopping
condition for substantive overlap or evidence against the core claim.

## Idea 的评估与推进（用户原文，2026-10-16）

### 1. 基本态度

标题为助手所加，正文为用户原文：

> 我们并不追求“绝对原创”或“从未有人做过”的完美 idea，也不要因为已有相似工作就过度防御性地否定一个方向。已有方法在相关问题上的尝试，并不意味着这个思路失去了价值；只要我们能够与现有工作形成清晰且有意义的差异，进一步推进、完善或深化某个思想，解决已有方法的不足，或者从新的视角重新组织问题并讲出一个更完整、更有说服力的故事，这个 idea 就是可行的。判断的重点应是是否存在明确的新增贡献和进一步探索空间，而不是是否完全没有先例。

### 2. 检查 idea novelty

> 对于我提供的 idea，默认应优先尝试保留和发展它，而不是因为存在相似工作就轻易否定。首先，请系统调研一批与该 idea 最接近的论文，并尽可能深入阅读其核心方法、问题设定、技术细节和贡献边界，避免仅凭标题、摘要或表面相似性做出猜测。基于这些工作，分析我们的 idea 与现有方法之间真正的差异，并尝试用一段清晰、有说服力的话论证其 novelty，包括我们具体新增了什么、推进了什么，以及为什么这种差异是有意义的。但不要为了保留 idea 而强行制造 novelty：如果调研后发现与已有工作在核心问题、关键方法和主要贡献上的确存在不可绕过的高度重合，已经难以形成实质性区分，则应停止论证，并明确指出与哪些工作严重撞车、具体重合在哪里，以及为什么现有差异不足以支撑一个可信的 novelty claim。

### 3. 推进 idea 实现与实验

适用场景（用户原文）：经过讨论可能已经基本确定了一个 idea 或者某个故事，然后需要进入实现和实验的讨论。我希望好好基于此讨论，优先尝试保留和发展它，而不是去轻易否定。

> 当我们已经基本确定一个研究 idea、方法方向或论文故事，准备讨论实现与实验时，请把它作为当前的工作假设，优先帮助我将其具体化、做扎实，而不是重新从零审查它是否值得做。
>
> 请围绕这个方向讨论：核心主张需要什么样的实现来支撑，哪些设计选择最关键，应该设置什么基线、消融和诊断实验，以及什么结果能够支持或挑战我们的解释。遇到技术困难、相似工作或实验风险时，先尝试提出仍然保留核心思想的调整方案，并说明各方案的代价和验证方式；不要仅因存在困难或不确定性，就轻易建议放弃方向或换一个故事。
>
> 请明确区分“需要通过实验回答的不确定性”“可以通过实现调整解决的问题”和“可能动摇核心主张的关键风险”。对于最后一类，请给出具体依据、最小验证实验和可能的修正路径。只有当关键证据确实表明核心主张难以成立时，再建议重新考虑方向。我们的目标是建设性地推进这个 idea，同时用严格的实现和实验检验它。
