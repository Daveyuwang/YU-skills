Making LLMs Faster and Cheaper

A trained language model needs a lot of memory and compute every time it answers. For example, a 70B model stored with 16 bits per number needs about 140 GB of memory just for its weights, and it must run once for each word it writes. This map covers ways to make that cost smaller: fewer bits, smaller models, faster generation, less memory and better use of hardware. Training the model in the first place is in the LLM Pre-training map.

Each paper below has an arXiv link and one simple sentence. Results are the numbers the authors report, and they were not rerun here. Links were checked against arXiv on November 2, 2026.

The 7 branches
Quantization: Storing each number in the model with fewer bits. First paper: GPTQ.

Smaller models: Removing parts of a model, or teaching a small model to copy a large one. First paper: SparseGPT.

Faster generation: Writing several words per step instead of one. First paper: Fast Inference via Speculative Decoding.

Memory for long inputs: Reducing what the model must remember about earlier words. First paper: CacheGen.

Routing and reuse: Using a cheap model when it is enough, and reusing past answers. First paper: Large Language Model Cascades.

Serving many people: Sharing one set of GPUs across many requests. First paper: vLLM.

Hardware and energy: What the chips do while the model runs and how much power it takes. First paper: LLM Inference Unveiled.

Words you will see
Inference: running a trained model to get an answer.

Token: a piece of text, usually a word or part of a word.

Latency: how long someone waits for an answer.

TTFT: time to first token, the wait before the first word appears.

Throughput: how many tokens a system writes per second in total.

Quantization: storing numbers with fewer bits, such as 4 bits instead of 16.

Pruning: removing weights or whole parts of a model.

Low-rank: replacing a big matrix with two small ones that multiply to nearly the same result.

Distillation: training a small model to copy a large one.

Speculative decoding: a small model guesses several words, and the large model checks them all in one step.

Early exit: stopping before the last layer when the model is already confident.

KV cache: the stored keys and values of earlier words, which the model reuses for each new word.

Sparse attention: looking at only some earlier words instead of all of them.

Prefix caching: reusing the KV cache when two prompts start with the same text.

Semantic caching: returning a saved answer when a new question means the same thing as an old one.

Routing: choosing which model should answer each question.

Prefill and decode: reading the prompt, then writing the answer. They stress the hardware differently.

Disaggregation: running parts of inference, such as prefill and decode, on separate machines.

NPU: a low-power chip for AI in phones and laptops.

FPGA: a chip whose circuits can be rewired for one job.

Quantization
Good papers to start with
A Survey of Quantization (Mar 2021): A broad introduction to the methods and the math.

Integer-Arithmetic-Only Inference (Dec 2017): An early method for running neural networks using only 8-bit integers.

LLM.int8() (Aug 2022): Makes 8-bit multiplication work for very large transformers.

GPTQ (Oct 2022): Compresses weights to 3 or 4 bits after training, using second-order information.

SmoothQuant (Nov 2022): Moves difficulty from activations to weights, so that both can use 8 bits.

AWQ (Jun 2023): Protects the weights that matter most, chosen by looking at activations.

QLoRA (May 2023): Fine-tunes a model that is already quantized, which also shows what 4-bit storage can do.

A Survey on Model Compression (Aug 2023): An overview of compression methods for language models.

Why quality drops
Signal and noise (Aug 2026): Finds that damage depends on where errors enter and how they build up through the network.

Expressive power (Jun 2026): A theory of how much a model can represent as the number of bits goes down.

Smoothness (May 2026): Argues that extreme quantization must keep the model smooth, not only keep its numbers close.

Fidelity metrics (Jun 2026): Finds that common metrics measure how much a quantized model disagrees, not which way.

Saying, not knowing (Oct 2026): Finds that heavily quantized small models can write fluent text that has lost its meaning.

Does compression preserve uncertainty? (Jun 2026): Finds that accuracy alone is not enough for judging a compressed model.

New methods
Replay the Curvature (Sep 2026): Quantizes a 397B model, with per-layer time cut by over 15x compared with a popular tool.

Trainable Vector Quantization (Oct 2026): Reaches 2 bits on a 70B model with only a 1% accuracy drop.

MoBiQuant (Feb 2026): Lets one model change its precision token by token while running.

OffQ (Jun 2026): Handles outlier values in a structured way, so that low-bit models lose less accuracy.

LoopQ (May 2026): Adapts quantization to models that repeat the same layers.

The Era of 1-bit LLMs (Feb 2024): Builds models with weights of only -1, 0 and 1.

BitNet (Oct 2023): An earlier 1-bit transformer trained from scratch.

Dynamic sparsity (Nov 2025): Combines quantization and sparsity for up to 1.55x faster decoding on ordinary GPUs.

Practical guides
Which quantization should I use? (Jan 2026): A guide to choosing among llama.cpp formats.

SLMQuant (Nov 2025): Benchmarks quantization on small language models.

Mixed-precision techniques (Oct 2025): A review of using different numbers of bits in different places.

Quantizing diffusion language models (Apr 2026): Finds that diffusion language models may handle quantization better than usual ones.

Distillation and small models

RecurrentGemma (Apr 2024): Replaces transformers with a recurrent design for efficiency.

Faster generation
Good papers to start with
Speculative Decoding (Nov 2022): A small model writes a draft, and the large model checks it in one step.

Speculative Sampling (Feb 2023): The same idea, published independently at about the same time.

Medusa (Jan 2024): Adds several extra heads to predict multiple tokens at once, with no separate model.

EAGLE (Feb 2024): Drafts using the large model's hidden features instead of raw text.

EAGLE-2 (Jun 2024): Builds a tree of drafts whose shape depends on confidence.

Inference with Reference (Apr 2023): Copies from the prompt, which suits tasks such as editing.

Performance or illusion? (Dec 2025): Measures real speedups and finds large gaps against theoretical limits.

Approximate Speculative Decoding (Aug 2026): Allows small differences from the target model in return for more speed.

3-Model Speculative Decoding (Oct 2025): Adds a third, medium model between the draft and the target.

FastMTP (Sep 2025): Improves multi-token prediction, outperforming the basic version by 82%.

Disparate impacts (Oct 2025): Finds that speedups are not equal across types of prompts, and proposes a fix.

Diffusion models change speed (Oct 2026): Finds that the speed benefit depends on how much of the output is already determined.

Stopping early

Some questions for inspiration
How many bits can a small model lose?: Quantize one small model to 8, 6, 4 and 2 bits, then plot its accuracy.

Which prompts does speculative decoding really speed up?: Run a small draft model with a larger target, then compare speedups on math, code and chat prompts.

How much of the KV cache can you drop?: Keep only part of the cache on a long prompt, then plot accuracy against memory saved.

Does a simple router beat random choice?: Send questions to a small or a large model with one simple rule, then compare cost and accuracy with random choice.

Where is your own computer's sweet spot?: Time a local model at several prompt and answer lengths, then plot tokens per second.
