LLM Agents

A trained language model can only write text, so it cannot fix a bug by itself. An agent puts the model in a loop: it reads a bug report, asks to open a file, sees the file, asks to run the tests, sees them fail, edits the code and tries again until the tests pass. This map covers how to get a trained model to finish long tasks this way. How the model gets trained in the first place is in the LLM Pre-training and LLM Post-training maps, and attacks on agents are in the LLM and Agent Safety map.

Each paper below has an arXiv link and one simple sentence. Results are the numbers the authors report, and they were not rerun here. Links were checked against arXiv on November 2, 2026.

The 7 branches
Tools and skills: How a model asks for a search, a calculator or any other program. First paper: Toolformer.

Planning and harnesses: The loop and the software around the model that keep a long task on track. First paper: ReAct.

Memory: What an agent keeps when its task is longer than the model can read at once. First paper: MemGPT.

Coding agents: Agents that read a repository, edit code and run tests. First paper: SWE-agent.

Research, web and computer use: Agents that search, click through websites and use a desktop. First paper: WebGPT.

Many agents together: Several models that split a task and pass work between them. First paper: AutoGen.

Training and testing agents: How to teach an agent with practice, and how to measure what it can do. First paper: AgentBench.

Words you will see
Agent: a model running in a loop, where it acts, sees the result and decides what to do next.

Tool: a program the model can ask to run, such as web search or a test runner.

Function calling: the model writes a tool name and its inputs in a fixed format.

Tool schema: the text that tells the model what a tool does and what inputs it takes.

MCP: Model Context Protocol, a shared standard for connecting tools to models.

Skill: a saved set of instructions the agent can load when a task needs them.

Harness: all the software around the model, such as the loop, the tools and the rules for stopping.

Context: everything the model can read at the current step.

Context window: the most text a model can read at once.

Compaction: replacing old parts of the context with a short summary to make room.

Trajectory: the full record of one run, with every thought, action and result.

Long horizon: a task that takes many steps or a long time.

Subagent: a helper agent that gets one part of the task and reports back.

Orchestrator: the agent that hands out work to other agents.

Computer use: an agent that sees the screen and uses the mouse and keyboard.

Deep research: an agent that searches many sources and writes a long report with citations.

Agentic RL: reinforcement learning where the model practices whole tasks and gets a reward at the end.

Test-time scaling: letting an agent use more steps, or more attempts at once, while it is being tested.

Time horizon: how long a task an AI can finish, measured by the time it takes a person.

Benchmark: a fixed set of tasks used to compare systems.

MetaGPT: Agents that act as a small software company. https://github.com/FoundationAgents/MetaGPT

SWE-bench: Runs the benchmark of real GitHub issues. https://github.com/SWE-bench/SWE-bench

MLE-bench: Tests agents on machine learning tasks. https://github.com/openai/mle-bench

AgentBench: Tests models as agents across several environments. https://github.com/THUDM/AgentBench

Some questions for inspiration
Does a shorter tool list help?: Give one small agent 5, 50 and 500 tools, then count how often it picks the right one. https://arxiv.org/abs/2605.26165

How much context can an agent lose?: Summarize old steps at several strengths on the same tasks, then plot success against tokens saved. https://arxiv.org/abs/2609.32961

Does memory help on a repeated task?: Run an agent twice on similar tasks with and without notes from the first run, then compare. https://arxiv.org/abs/2511.20857

Does a coding score survive renaming?: Rename the files and variables in a few benchmark tasks, then compare the agent's scores before and after. https://arxiv.org/abs/2609.27891

When is a helper worth its tokens?: Run the same tasks with and without a subagent, then compare success and tokens used. https://arxiv.org/abs/2610.22869
